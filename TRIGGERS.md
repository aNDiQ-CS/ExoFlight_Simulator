# Триггеры, диалог и контрольная точка

## Быстрая проверка

Открой `ExoFlight/Assets/Scenes/TriggerTest.unity`, нажми Play и щёлкни по Game. Игрок появляется перед бирюзовыми воротами. Управление: WASD и мышь; Esc освобождает курсор.

1. **01 — Dialogue, бирюзовые:** последовательно проигрываются два тестовых радиосигнала. Дождись окончания обоих.
2. **02 — Debug Log, оранжевые:** в Console появляется сообщение `[Mission] Телеметрия получена…`.
3. **03 — Checkpoint, фиолетовые:** сохраняется новая точка возврата — круг за третьими воротами.

Отойди в сторону и нажми **R**, пока курсор захвачен игрой: игрок вернётся к новой точке. Падение на 20 метров ниже текущей контрольной точки тоже возвращает игрока. До прохождения третьей зоны R возвращает к старту.

Можно обойти первые ворота и сразу зайти во вторые или третьи: действия не сработают. Если вошёл в следующую зону до окончания диалога, нужно выйти и войти снова. Одновременное пересечение перекрывающихся зон не позволяет пройти два шага за один вход. Завершённые шаги не повторяются.

После возврата к контрольной точке прогресс последовательности сохраняется. После остановки и нового запуска Play Mode прогресс и контрольная точка сбрасываются. Сохранения между запусками приложения здесь пока нет.

## Что где находится

| Объект / файл | Назначение |
| --- | --- |
| `XR Origin (XR Rig) / Player Trigger Sensor` | Отдельная капсула с `Is Trigger` и кинематическим Rigidbody. Следует за капсулой игрока; не толкает объекты. |
| `PlayerCheckpoint` на корне игрока | Сохраняет позицию и поворот точки возврата, предоставляет `Save()` и `Respawn()`. |
| `Trigger Mission - ordered steps / TriggerSequence` | Список `Steps`: зона и её действие. Порядок элементов задаёт порядок прохождения. Здесь же хранится текущий прогресс в памяти. |
| `TriggerZone` на воротах | Принимает `OnTriggerEnter` только от `PlayerTriggerSensor`. Обычный коллайдер игрока, руки и предметы игнорируются. |
| `Assets/TriggerDemo/01_Dialogue.asset` | Настройка действия «проиграть диалог». Ссылается на `DemoDialogue.asset`. |
| `Assets/TriggerDemo/02_DebugLog.asset` | Редактируемый текст для Console. |
| `Assets/TriggerDemo/03_Checkpoint.asset` | Действие «сохранить контрольную точку». Берёт Transform из поля `Checkpoint` своей зоны. |
| `Assets/TriggerDemo/DemoDialogue.asset` | Реплики: говорящий, текст, аудиоклип, пауза после реплики. |
| `Assets/Audio/TriggerDemo` | Два синтезированных тестовых звука, без голосовой озвучки. |

Солидный `CharacterController` продолжает отвечать за ходьбу и стены. Триггерная капсула — отдельный дочерний объект. Её слой `Ignore Raycast` не мешает XR-лучам; взаимодействие триггеров этого слоя со слоем зон должно оставаться включённым в Physics Settings.

## Зачем здесь ScriptableObject

ScriptableObject хранит редактируемые данные в отдельном `.asset`-файле. Например, `DemoDialogue.asset` — это список реплик, который можно назначить разным диалоговым действиям. Он не является компонентом сцены и сам по себе ничего не проигрывает. За проигрывание отвечает `DialoguePlayer` с AudioSource.

Важное разделение: **данные диалога и действий — в assets, текущее состояние прохождения — в компонентах сцены**. Поэтому использование одного asset в двух местах не означает общий счётчик пройденных шагов.

Подробнее: [ScriptableObject в документации Unity](https://docs.unity3d.com/6000.0/Documentation/Manual/class-ScriptableObject.html).

## Как заменить звуки полноценными репликами

1. Импортируй свои аудиофайлы в Assets.
2. Выбери `Assets/TriggerDemo/DemoDialogue.asset`.
3. В `Lines` замени `Audio`, заполни `Speaker` и `Text`, настрой `Pause After`. Можно добавлять, удалять и переставлять реплики.
4. Каждый клип проигрывается до конца, затем выдерживается пауза. Только после всей последовательности открывается следующий триггер.

На `DialoguePlayer` есть событие `Line Started (speaker, text)` для будущих субтитров, портретов или анимаций и событие `Finished` для завершения диалога. Экранного интерфейса сейчас нет. Это основа линейного диалога; выбор ответов и ветвления пока не реализованы.

Новый диалог: **Assets → Create → ExoFlight → Dialogue**. Новое действие: **Assets → Create → ExoFlight → Triggers**. Затем назначь dialogue asset в `Dialogue Action` и добавь action asset в нужный шаг последовательности.

## Как собрать свою последовательность

1. На корне игрока добавь `PlayerCheckpoint`. Помести prefab `Assets/Prefabs/PlayerTriggerSensor.prefab` дочерним объектом с локальными Position/Rotation = 0 и Scale = 1. Для текущего XR-игрока капсула автоматически повторяет размеры CharacterController; для будущего дрона без CharacterController размеры можно задать в prefab.
2. Создай объект с `TriggerSequence` и `DialoguePlayer`. Добавь ссылку на Dialogue Player в последовательности. AudioSource должен быть включён; Play On Awake выключен.
3. Создай объекты зон, добавь `TriggerZone` и настрой размеры их BoxCollider с `Is Trigger`.
4. В `Steps` добавь пары **Zone + Action** в нужном порядке. Одна зона используется один раз в одной последовательности.
5. Для `Set Checkpoint Action` создай пустой объект в безопасном месте и назначь его в `Checkpoint` соответствующей зоны. Положение и поворот копируются при срабатывании, поэтому дальнейшее перемещение маркера не сдвигает уже сохранённую точку.

Для нового типа действия создай наследника `TriggerAction`, реализуй `Execute(TriggerContext)` и вызови `context.Complete()` после успешного завершения. В `CanExecute` проверяй необходимые ссылки. Асинхронное действие может использовать `yield return`; последовательность ждёт его завершения.

Если отключить объект последовательности во время диалога, звук остановится, незавершённый шаг не засчитается. После включения нужно войти в текущую зону заново. Отсутствующий диалог или клип выдаёт предупреждение и не пропускает шаг.

## Повторяемая проверка

При открытой `TriggerTest` и выключенном Play Mode выбери **Tools → ExoFlight → Run Trigger Demo Checks**. Проверка запускает Play Mode, использует реальные пересечения коллайдеров, затем останавливает его. Во время проверки держи Unity на переднем плане и не управляй игроком.

Результат: `ExoFlight/Temp/TriggerChecks.results.txt` и запись `Trigger checks` в Console. Проверяются фильтрация коллайдеров, порядок, прерывание диалога, блокировка следующей зоны, два клипа, перекрывающиеся зоны, отсутствие повторов и возврат по новой контрольной точке, включая падение и R.
